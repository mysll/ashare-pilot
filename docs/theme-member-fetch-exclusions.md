# 主题成分抓取排除清单

- 版本：1.1
- 日期：2026-08-04
- 范围：东方财富概念板块成分抓取、主题库构建、盘中概念 Dashboard
- 关联：`config/themes/theme-config.json`、ADR-0003、`theme-library` skill

## 1. 目的

主题库使用稳定的“主题 → 概念 → 股票”关系。指数样本、机构持仓、
价格风格、交易状态和一次性财报事件不构成稳定主题关系，却可能包含数百至
数千只股票。继续抓取这些板块会显著增加分页请求、断点数量和限流风险。

权威配置是 `config/themes/theme-config.json` 的
`member_fetch_exclusions`。清单中的概念保留板块元数据，但不请求成员页，
构建后以 `member_fetch_status: ignored` 和空成员列表存在。

排除项不得与 `themes.*.concepts` 重叠。抓取和构建命令均对此执行
fail-closed 校验。

## 4. 暂缓排除

### 4.1 盘中交易状态板块

以下板块不适合成为静态投资主题，但盘中 Momentum 计算仍需要它们：

- 昨日连板、昨日连板_含一字
- 昨日涨停、昨日涨停_含一字、昨日首板
- 昨日高振幅、昨日高换手、昨日触板、昨日炸板
- 最近多板、东方财富热股、趋势股、题材股
- 近期新高、百日新高、反转股、次新股
- 昨日打二板以上表现

其中 `昨日连板` 和 `昨日连板_含一字` 用于识别其他概念涨停股中的首板和
连板。除非盘中流程改为从独立涨停历史数据获得该集合，否则不得加入
`member_fetch_exclusions`。

不能因为成员多或尚未映射而直接排除。

## 5. Dashboard 边界

盘中 Dashboard 从实时概念排名中删除 `member_fetch_exclusions` 后再计算
Performance、Capital、Breadth、Momentum 和 Composite。为尽量维持调用方
请求的 `top` 数量，数据源一次请求 `top + 排除项数量`，过滤后截取 `top`；
不会为排除项发起成员请求。

交易状态板块没有加入排除清单，因此 `昨日连板` 辅助集合仍然可用。

## 6. 后续维护流程

每季度以及财报窗口结束后执行一次复审：

1. 刷新 `concepts.json`，统计全部概念、主题引用概念和未引用概念。
2. 新概念先判断是否具有稳定产业、技术、政策或供需语义。
3. 只有指数样本、持仓、上市属性、价格/市值风格、交易状态或过期事件才进入
   排除候选。
4. 检查候选与 `themes.*.concepts` 的交集必须为空。
5. 检查盘中 Dashboard 或其他流程是否直接依赖候选成员。
6. 更新本文件的基线、理由、延期项和复审日期。
7. 运行抓取、构建及完整回归测试。

增加排除项后，下一次批量抓取会写入 `ignored` 标记并删除其分页断点。
移除排除项后，旧 `ignored` 标记不再视为有效缓存，下一次批量抓取会自动恢复
成员请求；也可使用 `--concept BKxxxx` 单独恢复并验证。

## 7. 不采用的规则

- 不自动排除所有未被主题引用的概念。
- 不以单次盘面热度或成员数量作为排除理由。
- 不以主观的“不常用”作为排除理由，除非未来建立了可审计的查询频率数据。
- 不排除主题已引用概念；需要移除主题关系时，必须先单独评审主题配置。

## 8. 2026-07-23 分页请求验证

使用 `BK1749` 对生产请求形态进行了独立 live 验证：按涨跌幅降序、每页
50 条、固定 Windows Chrome 指纹、持久 HTTP Session、板块级 Referer、
网页 `ut`、JSONP 和 3–5 秒随机间隔。连续 11 页均返回 HTTP 200、
`rc=0`，最终获得 550/550 个唯一成员。

可重复测试位于 `tests/integration/test_theme_pagination_live.py`。默认测试套件
不会访问网络；只有显式设置 `ASHARE_LIVE_EASTMONEY=1` 才会使用本地
`.cookie` 运行。
